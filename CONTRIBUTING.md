# Contributor Guidelines

Thanks for checking out Aurea Engine! If you would like to contribute in any form, please read this document first.

Credit to Godot's guidelines and [Contributing-Gen](https://contributing.md/generator/) for help with wording and what to include.

> ### Legal Notice
> When contributing to this project, you must agree that you have authored 100% of the content, that you have the necessary rights to the content and that the content you contribute may be provided under the [project license](https://github.com/mocacola02/AureaEngine/blob/main/LICENSE).

## Reporting Bugs

Issues can be created and searched for on the [Issues](https://github.com/mocacola02/AureaEngine/issues) page.

**Before submitting a new issue, please search for any existing issues that might help you or address the problem. If a pre-existing issue exists, please leave a comment on it rather than creating a duplicate issue.**

Please follow any instructions provided in the issue template you select.
When possible, please include basic project files that reproduce the issue being reported. Additionally, please make sure the issue applies to the latest stable release of the engine. Issues for old versions will be disregarded unless still present in the stable release.

## Proposing Features
Please be clear and descript when requesting new features. Please note that in the engine's early stages, feature requests are likely going to be very low priority while core engine features are still being implemented.

## Contributing Pull Requests
Godot's contribution guidelines put it best:

>If you want to add new engine features, please make sure that:
> - This functionality is desired, which means that it solves a common use case that several users will need in their real-life projects.
> <br><br>
> - You talked to other developers on how to implement it best.
> <br><br>
> - Even if it doesn't get merged, your PR is useful for future work by another developer.

Some additional considerations:

- Please make PRs simple and focused on one feature or issue, don't submit PRs tackling a ton of issues at once. If you have multiple contributions to make, please use multiple PRs.


- Please keep commit messages clear and concise while being clear on what was added/changed and where.


- Consider including a test for contributions to ease the testing and QA process.


### Disclaimer Regarding AI
As of writing this (9/10/2026), this engine is written purely by myself. I have experience designing game systems, starting off as a modder for an Unreal Engine 1 game and eventually moving to Godot.
I have been using this project as an opportunity to learn C++ and combine aspects of both UE1 and Godot that I enjoy.

I have utilized IBM Granite 4.2, [a model which has been ranked as a leader in responsible AI with ethically sourced data](https://research.ibm.com/blog/granite-ethical-ai), on my own local computer for assistance with concepts I am unfamiliar with. I cross-reference any information with additional online sources to ensure accuracy. I still write all code, with any AI suggestions being heavily scrutinized. If there is a mistake in code, it is due to my own error or misunderstanding, not due to "vibe coding".
All documentation is written myself (besides the auto-generated aspects from Doxygen), including the repo's README and CONTRIBUTING documents (if it seems wordy, that's just how I write, ask anyone).

**Fully AI-generated code contributed will not be accepted.** I believe AI is a useful tool for developers, but it is not a replacement for writing, proofreading, and testing your own code. I also encourage using ethically trained models on a local device, but that is something I can't really enforce. If you have capable hardware, I'd recommend giving local models a shot. Better to  run it yourself than pay an untrustworthy company an overpriced fee to ruin the environment.

**Images, video, audio, etc. generated even partially with AI will not be accepted. This includes using AI generated content as a base template or reference. I personally do not agree with its use outside of learning and programming assistance, primarily due to concerns over stolen training data taken from real artists.**
